# Lab 10 – Wireshark Traffic Analysis in a Segmented Network

## Objective

Use Wireshark to capture and analyze network traffic across the segmented Active Directory environment created in the previous pfSense labs.

This lab builds on my earlier Wireshark analysis by examining traffic after CLIENT and DC01 were moved behind the pfSense firewall. I generated specific network activity and used packet captures to verify communication between CLIENT, DC01, and the pfSense gateway.

## Lab Environment

- pfSense firewall/gateway: `192.168.1.1`
- Domain Controller / DNS Server (DC01): `192.168.1.10`
- Domain-joined workstation (CLIENT): `192.168.1.101`
- Internal network: `192.168.1.0/24`
- Wireshark

## ICMP Connectivity Analysis

I first generated traffic between CLIENT and the pfSense gateway using:

```cmd
ping 192.168.1.1
```

I filtered the capture using:

```text
icmp
```

Wireshark showed ICMP Echo Requests traveling from CLIENT (`192.168.1.101`) to pfSense (`192.168.1.1`) and Echo Replies returning to CLIENT.

This confirmed connectivity between the workstation and its default gateway while also showing how the communication appeared at the packet level.

The capture shows successful ICMP request and reply traffic between CLIENT and the pfSense gateway.

## DNS and SMB Validation

DNS and SMB were previously examined in my earlier Active Directory Wireshark lab.

In this lab, I captured these protocols again to verify that normal Active Directory network communication continued to function after moving the environment behind pfSense.

### DNS Validation

I generated DNS traffic using:

```cmd
nslookup google.com
```

I filtered the capture using:

```text
dns
```

The capture showed DNS communication involving CLIENT (`192.168.1.101`) and DC01 (`192.168.1.10`).

CLIENT continued to use DC01 as its DNS server after the network was moved behind pfSense.

### DNS Capture

![DNS Traffic](nslookup%20google.com%20.png)

The capture shows DNS activity generated from CLIENT while resolving `google.com`.

### SMB Validation

I accessed DC01 from CLIENT and browsed the available domain shares, including `NETLOGON` and `SYSVOL`.

I filtered the capture using:

```text
smb2
```

Wireshark showed SMB2 communication between CLIENT (`192.168.1.101`) and DC01 (`192.168.1.10`).

This confirmed that SMB communication between the domain workstation and Domain Controller continued to function on the segmented network.

## Kerberos Authentication Analysis

I also generated new Kerberos authentication traffic to examine domain authentication within the segmented network.

I cleared the existing Kerberos tickets on CLIENT using:

```cmd
klist purge
```

I then locked the workstation and logged back into the domain account.

I filtered the capture using:

```text
kerberos
```

The capture showed Kerberos communication between CLIENT and DC01, including:

- AS-REQ
- AS-REP
- TGS-REQ
- TGS-REP

The AS exchange is associated with obtaining a Ticket Granting Ticket (TGT), while the TGS exchange is used when requesting tickets for specific services.
